# Dead Code & Duplication Audit — Tazella

**Date:** 20 November 2026
**Scope:** full repository — Expo app (`app/`, `src/`), Next.js web app (`web/`), Supabase (`supabase/`), scripts, tests, CI and docs.
**Mode:** read-only audit. No source files were changed by this audit.
**Goal:** find code that can be removed or shared so the system is smaller, easier to read, and cheaper to run per concurrent customer.

---

## 1. Executive summary

### Measured baseline

| Area | Files | Source lines |
|---|---:|---:|
| `web/` | 273 | 64,059 |
| `supabase/` | 142 | 32,216 |
| `src/` (Expo shared) | 88 | 17,914 |
| root config / schemas / lockfiles | 15 | 16,086 |
| `app/` (Expo routes) | 104 | 14,573 |
| `docs/` | 19 | 3,105 |
| `content/` | 2 | 1,484 |
| `scripts/` | 2 | 1,310 |
| `tests/` | 4 | 688 |
| `.github/` | 2 | 83 |
| **Total** | **654** | **151,570** |

Lockfiles alone are ~20,300 lines (root 13,703 + web 6,588). Excluding lockfiles, the source tree is ~131,000 lines.

### Headline findings

1. **The largest duplication is structural, not accidental.** The entire vendor and enterprise advertising flow is five page pairs that are byte-identical except one line (`requireAdvertiser()` vs `requireAdvertiser({ prefer: 'enterprise' })`). **~1,100 lines** can become five thin route wrappers over shared components.
2. **A whole legal document copy is dead.** `content/legal/{en,ar}.json` (1,484 lines) is never referenced; byte-identical copies live in `src/legal/` and `web/lib/legal/`.
3. **The Expo app statically ships ~2,285 lines of mock catalog data** that is unreachable when Supabase is configured (which it is in shipped builds). This is the single biggest bundle/parse win for low-end devices.
4. **There is no dead-route problem in `web/`.** Every page, API route, component and lib module is reachable. Dead code in the web app is almost entirely *duplication*, not orphaned files.
5. **The hottest CPU path re-reads configuration from the database on every provider call.** `mfConfig()` in the Edge Function shared client queries `system_settings` on each checkout/webhook, often twice per request. This is the cheapest high-impact performance fix.
6. **Applied SQL migrations are historical record.** ~5,553 lines of superseded function definitions exist in migration history, but must **not** be deleted; they are what lets a fresh database rebuild. Treat that number as source-readability debt only, not removable code.

### Shrink estimate

| Scenario | Removable lines | % of source text | Risk |
|---|---:|---:|---|
| Conservative — dead files/exports/keys, dead legal copy, safe duplicates | **~5,900** | ~3.9% | Low–medium |
| + full mock-data removal, deeper cross-app sharing, glyph/font cleanup | **~9,400** | ~6.2% | Medium |
| Migration squash (not recommended as part of this work) | +~5,553 | +3.7% | High |

The line-count reduction is modest, but the *runtime* payoff is larger than the percentage suggests: it removes a 2,285-line static bundle from the mobile app, a large unused npm dependency from the web build, several per-request DB round-trips from hot paths, and an N+1 view used by both apps.

## 2. What must NOT be removed

These were checked and are intentional:

| Item | Why it stays |
|---|---|
| All applied migrations in `supabase/migrations/` | They are immutable history; CI rebuilds a database by replaying them. Superseded function definitions are expected. Clean live objects only with **new** migrations. |
| RLS policy repetition (~1,200 SQL lines) | Security-sensitive and deliberately explicit per table. Refactor only with strong test coverage, if ever. |
| `src/legal/{en,ar}.json` and `web/lib/legal/{en,ar}.json` | Legal content, statically imported. The dead copy is `content/legal/`, not these. |
| Historical documents (`payment-processing-architecture.md`, `ADVERTISING_SYSTEM_PLAN.md`, `docs/HANDOVER-REVIEW.md`, `docs/fixes-20-2026.md`, phase audit docs) | Explicitly labeled historical planning/fix records. Archive by decision, not deletion. |
| `AGENTS.md`, `web/AGENTS.md` | Agent instructions; `web/AGENTS.md` is regenerated by `next dev`. |
| `expo-symbols`, `react-native-svg`, `react-native-screens`, `react-native-web`, `react-dom` | Framework or peer dependencies with no direct import but required by Expo Router / QR / web targets. |
| `web/lib/public-cache.ts` `cache()` + `unstable_cache()` pattern | Already optimized; the anonymous public homepage does parallel queries and tagged caching. |
| React `cache()` on web auth guards | Already deduplicates per request; do not remove. |

## 7. Prioritized roadmap

### Phase 0 — zero/low-risk quick wins (1–2 days)

1. Delete dead Expo files/exports/keys listed in §3.1 (after the `send/preview.tsx:59` link fix).
2. Remove `SpaceMono` font, `@expo-google-fonts/cairo`, and `pdfjs-dist`.
3. Delete `content/legal/` and `supabase/seed-demo-complete.sql`.
4. Fix stale FileType comment; make the Edge Function call `public.myfatoorah_file_type()`.
5. Fix `admin-supplier.ts:119` `revalidate()` bug during dedupe.

**Expected:** ~3,000 lines, no behavior change.

### Phase 1 — structural dedupe (3–5 days)

6. Extract the five shared advertising page components (§4.1).
7. Extract `web/lib/actions/_form.ts`, shared API-route helpers, shared identity loader.
8. Consolidate vendor/enterprise small dashboard wrappers.
9. Centralize status→tone maps and select-column constants in both apps.

**Expected:** ~1,800 additional lines; lower bug surface from one canonical implementation.

### Phase 2 — cross-app shared module (1–2 weeks, needs a decision)

10. Create `packages/shared/` (or a tsconfig path alias) for search, IBAN, tone, money formatting, app-config schema/defaults, and legal content.
11. Add contract tests so the web and Edge Function copies of validation stay synchronized.
12. Decide demo-mode policy, then either remove `mock-data.ts` completely or dynamic-import it.

**Expected:** ~2,000–3,500 additional lines plus a large bundle reduction.

### Phase 3 — runtime cost reduction (ongoing)

13. Implement P0/P1 performance items in §5.
14. Add CPU regressions to CI: query-count assertions in `tests/db` and a bundle-size check.

### Phase 4 — not recommended as part of this work

- Squashing applied migrations.
- Refactoring RLS policies for line count.
- Moving money math out of SQL into TypeScript.

## 9. Conclusion

The codebase is not rotting with orphaned files in `web/` — it is *repeating itself*. The highest-value work is:

1. **One shared advertising flow** instead of two identical copies.
2. **One legal/validation/formatting source** instead of two or three per concern.
3. **No mock data in the production mobile bundle.**
4. **No per-request config reads or duplicated DB queries on checkout and dashboard hot paths.**

Doing Phases 0–2 removes roughly **5,900–9,400 lines** and, more importantly, reduces the number of places a bug can hide and the amount of work each concurrent customer forces the system to do.
